# Stage 9 local Android tester

Use `build/stage9/whatmeal-local-tester.apk`. It is a release-mode **emulator-only tester**, signed with the existing Android Debug certificate. It is not a production release. Do not install the superseded Stage 7 APK.

- Package: `com.example.whatmeal.local`; version 1.0.0 (1).
- Firebase: native and Dart demo project `demo-whatmeal-audit`.
- Config locations: `firebase.audit.json`, `android/app/src/local/google-services.json`, `lib/main.dart`.
- Auth: 9099; Firestore: 8180; Android host alias: `10.0.2.2`.
- Min SDK 24 / target 36; ARMv7, ARM64 and x86-64 included.
- SHA-256: `F2CCEBB8BE48BE08C06A10C1061F2721B07DD4EA57345B954CFAC4E49279B5B2`.
- Compiled network policy denies general HTTP, permitting only 127.0.0.1 / localhost / 10.0.2.2 without subdomains. Native messaging and analytics auto-init are false. Local startup rejects an unexpected Firebase project.

No approved live non-production Firebase project is configured. Do not supply production data or live AI credentials. Local testing does not certify real email delivery, AI, push or production readiness.

## Reproduce the isolated session

Start only the demo backend:

```powershell
firebase emulators:start --only auth,firestore --project demo-whatmeal-audit --config firebase.audit.json
```

This host needs the process-local Java selector workaround documented in `COMMANDS.md`. Redact generated email action links from captured backend logs.

The workspace AOSP API 35 AVD is `whatmeal-stage9-aosp`, under `build/audit-avds`. The existing emulator 36.6.11 runtime with `-gpu host -memory 1536 -cores 2 -port 5564 -no-window -no-audio -no-snapshot` completed the final tests. Verify `adb -s emulator-5564 emu avd name` before installation. Ports 5554/5555 conflicted with an unrelated emulator and must not be assumed to belong to this audit. No unrelated applications were disabled.

Build with the AVD stopped, one Flutter command at a time:

```powershell
$env:WHATMEAL_TESTER_SIGNING = 'true'
flutter build apk --release --flavor local --target lib/main.dart --dart-define=WHATMEAL_EMULATOR_HOST=10.0.2.2
```

Keep platform regeneration enabled when switching from integration/debug to release. Do not add `--no-pub`; it previously retained an incompatible test registrant. Never run concurrent Flutter builds/tests/analysis that regenerate platform files. The signing opt-in reuses the existing debug identity; no production signing key is bundled or generated by this stage.

Install only after checking package/project/signature/hash, then launch explicitly:

```powershell
adb -s emulator-5564 install -r build/stage9/whatmeal-local-tester.apk
adb -s emulator-5564 shell am start -W -n com.example.whatmeal.local/com.example.whatmeal.MainActivity
```

Stage 9 actually executed both commands (exit 0), cold-started to Sign In, captured `tester-startup.png`, and found no ANR. The broader 28-checkpoint workflow passed using the separate debug integration APK from the same app source. Typing in that workflow used Flutter's deterministic handler; clipboard, navigation, rendering and Firebase SDK operations were real. See `REPORT.md` for exact evidence and remaining gaps.
